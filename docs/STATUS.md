## Milestone 9: done (2026-10-26)
Backend in `backend/` (see backend/README.md): Node + TypeScript, Fastify 5, Prisma 7 on
SQLite, a WebSocket hub, zod validation, rate limiting, `.env.example`. `npm test` runs 20 API and
WebSocket tests; `./gradlew build` passes. Tested end to end with two clients on a local offline
server against the real backend (screenshots: docs/screenshots/m9-*.png).

- REST: `POST /auth` (Mojang hasJoined -> JWT, single-use serverId), `GET /users/:uuid`,
  `GET /me`, `PUT /me/cosmetics`, `PUT /me/profile`, `GET /health`. Inputs follow the client's own
  rules; players can't set their own badge.
- WebSocket `/ws`: rooms per server address; presence, emote relay and `profile_update` pushes.
  Identity comes from the token, never from what the hello claims. Message size, hello timeout,
  emote token bucket, strike limit and duplicate-connection handling.
- Client: `net/BackendSession` signs in with Mojang's joinServer (your access token only goes to
  Mojang) once you're in a world, renews before expiry, and sends the token in the socket hello.
  Your loadout is uploaded after sign-in and whenever it changes (debounced; includes switching
  config profiles). Other players see the change live through `profile_update`.
- Offline still works fully: no backend means no sign-in, nothing retried more than every few
  minutes, and your own cosmetics keep rendering from the local profile.
- Dev testing: backend `ALLOW_UNVERIFIED=true` plus client `-Darchangel.devAuth=true
  -Darchangel.allowOfflineUuids=true` lets offline dev accounts sign in through `POST /auth/dev`.

## Milestone 8: done (2026-10-26)
Shaders and visuals. Build passes; tested in a world by day and night, and with real Iris 1.10.8
+ Sodium 0.8.15 and a shader pack installed in the dev run folder (not shipped, not a dependency)
(screenshots: docs/screenshots/m8-*.png). All of it is visual or performance only.

- Post Effects module (Visuals, off by default): custom GLSL in
  `assets/archangelclient/shaders/post/` run through Minecraft's post chain right where vanilla
  runs its own (`GameRendererMixin`), so the HUD and menus are never touched.
  - Motion blur (`motion_blur.fsh`, blends with a persistent previous frame), bloom
    (`bloom_threshold` soft knee, two separable 5-tap Gaussian passes at 1x and 2.5x radius,
    `bloom_combine` screen blend), color grading + vignette + chromatic aberration in one pass
    (`grade.fsh`).
  - The chain is built in code from the settings (`shader/PostEffects`) and rebuilt only when a
    setting changes; passes for disabled effects are left out entirely.
- Nebula Sky module (Visuals, on): a seamless cube map (`textures/environment/nebula.png`, 3x2
  atlas of 512 px faces) generated by `tools/sky/nebula.py` from directional noise, so faces meet
  without seams. Drawn after the sky color and before the sun, moon and stars (`SkyRendererMixin`),
  fades in with vanilla's star brightness and out in rain. Modes: Night or Always; opacity; turns
  with the stars.
- Brightness module (Visuals): a 0-100% slider that drives vanilla's own Brightness option, so it
  can never exceed vanilla's "Bright". Not fullbright. Turning it off restores your old value.
- Shader Packs page (sidebar, only when Iris is installed): lists the packs Iris accepts in
  `shaderpacks/`, shows the active one, switches packs or turns shaders off, opens the folder.
  Talks to Iris by reflection (`shader/IrisBridge`) so Iris stays optional; if Iris changes its
  internals the page says so instead of crashing. Our post effects and nebula pause while a pack
  is rendering.
- FPS Boost module (Performance, off): vanilla particle setting (All / Decreased / Minimal), a
  particle cap (`ParticleEngineMixin`, drops new particles past the limit), and entity render
  distance (50-100% of vanilla's). Lists Sodium, Entity Culling, ImmediatelyFast and FerriteCore
  as installed (green) or recommended with a Modrinth link (amber). Turning it off restores your
  vanilla options (`performance/OptionOverride`).
- Module pages can now show read-only status lines (`Module#getNotes`).

## Milestone 7: done (2026-10-26)
Nametags. Build passes; tested with two clients on a local offline server against a mock
backend (screenshots: docs/screenshots/m7-*.png).

- `net/UserProfile` + `net/ProfileCache`: one profile per player from `GET /users/:uuid`
  (`{"displayName", "nameColor": "#RRGGBB", "badge", "cosmetics": {...}}`, 404 = not an
  Archangel player), cached 5 min, non-blocking, offline backoff. Cosmetics now read from the same
  profile (replaces the milestone 5 `/v1/cosmetics` call). A `{"type":"profile_update","uuid"}`
  message on the socket drops a cached profile. The socket moved to `/ws`.
- Badge: the wings logo as a bitmap-font glyph (`font/badge.json`, `textures/font/badge.png`,
  built by `tools/nametag/badge.py`), so it rides the vanilla nametag path (background, distance,
  sneaking) with no extra rendering. Shown for Archangel players and for yourself.
- Custom names: display name and color from the backend. Players on a scoreboard team keep the
  server's formatting (ranks) and only get the badge. A display name that differs from the account
  name is always followed by the real name in gray, so nobody can pass as someone else; names are
  limited to letters, digits, `_` and spaces.
- Nametags module (Nametags category): badge, custom names, background opacity, text shadow,
  show own nametag in third person, scale. Mixins: `AvatarRendererMixin` (name + own tag),
  `NameTagStorageMixin` (opacity, scale), `NameTagFeatureRendererMixin` (shadow). Which nametags
  are visible stays vanilla.
- Fix: Java's HTTP client tried an HTTP/2 upgrade on plain HTTP, which servers that also host a
  WebSocket reject; the API client and socket now use HTTP/1.1.
- Testing on offline servers: `-Darchangel.allowOfflineUuids=true` lets version 3 UUIDs fetch
  profiles (normally only real version 4 accounts do).

## Milestone 6: done (2026-10-26)
Emotes. Build passes; tested in a world, and sync tested with two clients on a local offline
server through a small WebSocket relay standing in for the backend (screenshots:
docs/screenshots/m6-*.png). Emotes are visual only: nothing is sent to the game server.

- Keyframe system in `emotes/anim`: Bedrock animation JSON as exported by Blockbench / used by
  GeckoLib (`AnimationLoader`). Per-bone rotation and position channels, `pre`/`post` jumps,
  Bedrock `lerp_mode` (linear, catmullrom, step) and GeckoLib `easing` names (sine, quad, cubic,
  quart, expo, back, elastic, bounce), and `loop` true / false / `hold_on_last_frame`.
- Rig: head, body, arms, legs and a `root` bone that moves/turns the whole player around the
  feet. Values are on the Java player rig (degrees; negative x swings an arm forward, positive z
  lifts the right arm sideways; positions in pixels, +y up). Head keys add to where you look.
- Poses are applied in `HumanoidModelMixin` (end of `HumanoidModel.setupAnim`), so armor, the
  cape and Archangel cosmetics follow; the root bone is applied in `AvatarRendererMixin#scale`.
  Emotes blend in (0.15 s) and out (0.2 s).
- 8 emotes: wave, dab, clap, floss, sit, bow (the required six) plus salute and cheer. Sources in
  `tools/emotes/animations.py` (writes `emotes/animations/*.animation.json`); icons drawn by
  `tools/emotes/icons.py`. Catalog: `emotes/catalog.json` (wheel order; resource packs can add).
- Emote wheel (`EmoteWheelScreen`): hold B (rebindable in Controls), point, release. A quick tap
  keeps it open for clicking; 1-8 pick directly; the middle cancels. Blurred world behind it,
  anti-aliased wedges generated at runtime (`WheelTextures`).
- Your camera switches to third person while you emote and back afterwards. Movement keys, jump,
  sneak or being pushed cancel the emote (also for other players: they stop when they move).
- Sync: `net/BackendSocket` keeps a WebSocket open to `ws://<archangel.api>/ws` (was `/v1/ws` until milestone 7) while you are
  in a world (retries 5 s up to 60 s, silent while offline). Protocol for milestone 9:
  - client -> backend: `{"type":"hello","uuid","name","server"}` on connect, then
    `{"type":"emote","emote":"wave"}` and `{"type":"emote_stop"}`.
  - backend -> client: `{"type":"emote","uuid","emote"}` and `{"type":"emote_stop","uuid"}`.
  - The backend should verify the uuid (Mojang session check) and only relay between players on
    the same `server`. Clients ignore unknown emotes, players not in their world, and floods.
- Emotes module (Emotes category): third person while emoting, show others' emotes, share mine.

## Milestone 5: done (2026-10-26)
Cosmetics. Build passes; tested on the title screen, in the Locker and in a world by day and
night (screenshots: docs/screenshots/m5-*.png). Everything is cosmetic and drawn with the normal
depth test, so nothing is ever visible through walls.

- `cosmetics/CosmeticRegistry`: resource reloader for `cosmetics/catalog.json` (merged across
  resource packs) and Blockbench models in `cosmetics/models/*.geo.json`
  (`model/BlockbenchModelLoader`: Bedrock geo 1.12 and legacy format, rotated cubes, mirrored UVs).
- Slots: cape (static or animated frames), wings (flap faster while moving/flying, spread when
  crouching), hat, halo (spin + bob), aura, swing trail, hit effect. 15 original cosmetics; all
  textures are generated by `tools/cosmetics/generate.py` (no Mojang assets).
- `render/CosmeticLayer`: one render layer on the player renderer. Capes replace the vanilla
  cape (`CapeLayerMixin`), hide under an elytra, and shift over a chestplate; models attach to
  head or body and scale over helmets. Emissive parts glow at night.
- Aura (your own player only): glowing silhouette shells, holographic afterimages while moving,
  a ring with a ripple under your feet and drifting motes. Hidden in first person.
- Swing trails: a glowing arc along the blade, rebuilt from the swing animation each frame so it
  is smooth at any FPS, with a matching crescent in first person. Weapons only by default.
- Hit sparks: a burst of blue (or violet) sparks and a flash where your hit landed.
- `CosmeticsScreen` (Locker): 3D preview with drag-to-rotate and try-on, tabs per slot, owned
  grid, equip/unequip (double-click a card). Opens from the title screen's Cosmetics button and
  Client settings > Cosmetics > Open Locker. Equipped items are saved per profile.
- Other players: `net/CosmeticProfileCache` fetches `GET /v1/cosmetics/<uuid>` from the backend
  (`-Darchangel.api`, default `http://127.0.0.1:8787`) on background threads, caches for 5 min,
  and backs off for 60 s while offline. Offline, every cosmetic is unlocked and only you see them.
- Settings (Cosmetics module): show own/others, aura intensity, afterimages and count, ring,
  particles, trails on weapons only, first-person trail, spark count.

Not tested yet: other players' cosmetics against a real backend (milestone 9 builds it).

200 HP husk (screenshots: docs/screenshots/m3-*.png).

- `hud/HudElement`: a Module with hidden x/y settings (0..1 of free space, so layouts survive

- Elements: FPS, CPS (left/right), Keystrokes (press animation, CPS on mouse buttons), Ping,

  your own vanilla attacks/clicks (`AttackEntityEvent`, `MouseClickEvent` via `MouseHandlerMixin`).
- Target HUD: shows only after you hit an entity, only while it's alive, within 8 blocks and in
  direct line of sight (`hasLineOfSight`), hides 1-3 s (default 2.5) after your last hit. Model
  preview, name, distance, eased health bar red -> yellow -> green, damage graph. Verified it hides
  when a block is placed between you and the target.
- `HudEditorScreen`: grid, center lines, snapping to screen edges/center and other elements with
  guide lines (hold Shift to disable), scroll to resize, arrow keys nudge, right-click opens the
  element's settings, Reset layout. Opens from Client settings > HUD > "Edit HUD Layout" or an
  optional keybind in vanilla Controls.

## 0.2.0

- Font: Inter SemiBold (regular) and Inter Bold (bold) replace Inter Medium/SemiBold.
  `FontSharpness` rasterizes our TTF fonts at the current GUI scale (`TrueTypeGlyphProviderDefinitionMixin`)
  and reloads just the fonts when the scale changes, so glyphs are never resampled. With Menu Style →
  "Smooth font everywhere", `CachedFontProviderMixin` maps `minecraft:default` to Inter.
- Pause menu: `PauseScreenMixin` adds a full-width "Client Settings" button above Disconnect.
- Cosmetics: 22 new catalog entries. New textures and the wizard hat, horns and cat ears models come
  from `tools/cosmetics/generate.py` (existing outputs are unchanged).
- Releases: `.github/workflows/release.yml` builds the jar and publishes release `v<mod_version>`.
